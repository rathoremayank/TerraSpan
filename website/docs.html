Getting Started

Welcome to TerraSpan! This guide will help you get up and running with multi-cloud infrastructure provisioning in minutes.

Prerequisites

  • Terraform >= 1.5.0
  • AWS, Azure, or GCP account (or all three)
  • Git for version control
  • Command-line interface (bash, PowerShell, etc.)

Quick Start

  1. Clone the repository: git clone https://github.com/your-org/terraspan.git
  2. Navigate to desired environment: cd infrastructure/aws/environments/dev
  3. Initialize Terraform: terraform init
  4. Plan deployment: terraform plan
  5. Apply configuration: terraform apply

Architecture

TerraSpan follows a modular, multi-layered architecture designed for scalability and maintainability.

Directory Structure

terraspan/
├── infrastructure/
│   ├── core/              # Shared configuration
│   ├── aws/              # AWS provider
│   │   ├── modules/      # Reusable AWS modules
│   │   └── environments/ # dev, staging, prod
│   ├── azure/            # Azure provider
│   └── gcp/              # GCP provider
├── website/              # Documentation website
├── docs/                 # Full documentation
└── .github/workflows/    # CI/CD pipelines

Core Modules

  • Networking: VPC, subnets, security groups, load balancers
  • Compute: EC2/VMs, container orchestration, app services
  • Storage: Object storage, databases, caching layers
  • IAM: Roles, policies, service accounts, permissions
  • Monitoring: Logging, alerting, dashboards, metrics

Installation

Step 1: Install Terraform

Download from terraform.io/downloads or use a package manager:

# macOS
brew install terraform

# Windows
choco install terraform

# Linux
sudo apt-get install terraform

Step 2: Configure Cloud Credentials

AWS: Set environment variables or use AWS CLI

export AWS_ACCESS_KEY_ID=your_access_key
export AWS_SECRET_ACCESS_KEY=your_secret_key

Azure: Use Azure CLI

az login

GCP: Use service account JSON

export GOOGLE_APPLICATION_CREDENTIALS=path/to/service-account.json

Configuration

Each environment uses a terraform.tfvars file for environment-specific values.

project_name = "terraspan"
environment  = "dev"
region       = "us-east-1"
vpc_cidr     = "10.0.0.0/16"

availability_zones = ["us-east-1a", "us-east-1b"]

tags = {
  Environment = "development"
  ManagedBy   = "Terraform"
  Project     = "TerraSpan"
}

Modify values for your deployment needs. Each environment (dev, staging, prod) has separate variable files.

Deployment

Manual Deployment

# Initialize Terraform working directory
terraform init

# Validate configuration
terraform validate

# Preview changes
terraform plan -out=tfplan

# Apply changes
terraform apply tfplan

Automated Deployment (CI/CD)

Push changes to the main branch. GitHub Actions will automatically:

  1. Validate Terraform format and syntax
  2. Run security scanning (Checkov)
  3. Generate and post terraform plans
  4. Wait for manual approval
  5. Deploy approved changes

Troubleshooting

Common Issues

Backend not initialized

Error: "Error: Backend initialization required"

Solution: Run terraform init to initialize the backend

Resource already exists

Error: "Error: resource already exists"

Solution: Import the resource using terraform import or clean up manually

Insufficient permissions

Error: "AccessDenied" or "Forbidden"

Solution: Verify cloud credentials have required IAM permissions
